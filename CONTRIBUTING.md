# Contributing to DBSARE

## Documentation-first workflow

```
Architecture
 → Documentation
 → Interfaces / Contracts
 → Implementation
 → Tests
 → Validation
 → Documentation Update
```

## Rules

- Do not claim unimplemented functionality.
- Do not silently change architecture.
- Record unresolved choices as architectural observations/open decisions.
- Preserve evidence provenance.
- Treat external/tool output as untrusted data.
- Never bypass permission controls.
- Keep security-sensitive changes auditable.

## Phase discipline

A phase is not considered complete until its documented acceptance criteria are satisfied.
